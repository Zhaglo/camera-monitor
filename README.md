# Camera Monitor

Учебный проект: эмулятор сетевой камеры и CLI-утилита для мониторинга нескольких устройств.

Эмулятор предоставляет HTTP API состояния и настроек камеры. Монитор конкурентно опрашивает устройства, обрабатывает ошибки и формирует JSON-отчёт. Проект позволяет воспроизвести разные условия работы: успешный ответ, задержку, недоступность устройства и HTTP-ошибку.

## Возможности

- Получение состояния камеры через `GET /state`.
- Изменение FPS через `PATCH /settings` с проверкой входных данных.
- Настройка идентификатора, задержки ответа и имитации HTTP 503 через переменные окружения.
- Конкурентный опрос нескольких камер через HTTPX и asyncio.
- Настройка адресов устройств и таймаута из командной строки.
- Обработка HTTP-ошибок, ошибок соединения и таймаутов.
- Вывод JSON-отчёта в терминал или сохранение в файл.
- Запуск трёх эмуляторов через Docker Compose.
- Автоматические тесты логики устройства, API и монитора.

## Технологии

Python 3.12, FastAPI, Pydantic, Uvicorn, HTTPX, asyncio, argparse,
logging, pytest, Docker и Docker Compose.

## Установка

Для локального запуска нужны Python 3.12 и Git.
Для запуска эмуляторов в контейнерах — Docker с Docker Compose.

```bash
git clone https://github.com/Zhaglo/camera-monitor.git
cd camera-monitor

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Команды активации окружения приведены для macOS и Linux.

## Быстрый запуск через Docker Compose

```bash
docker compose up --build -d
```

Compose запускает три устройства:

| Устройство | Адрес состояния | Поведение |
|---|---|---|
| camera-fast | http://127.0.0.1:8002/state | Ответ без искусственной задержки |
| camera-slow | http://127.0.0.1:8003/state | Задержка ответа 2 секунды |
| camera-failing | http://127.0.0.1:8004/state | HTTP 503 |

После запуска контейнеров выполните монитор в активном Python-окружении:

```bash
python monitor.py \
  http://127.0.0.1:8002/state \
  http://127.0.0.1:8003/state \
  http://127.0.0.1:8004/state \
  --timeout 3 \
  --output report.json
```

Два устройства должны успешно ответить, третье — попасть в отчёт
с HTTP-ошибкой. Благодаря конкурентному опросу общее время составляет
примерно две секунды, без учёта дополнительных задержек среды.

Без параметра `--output` JSON-отчёт выводится в терминал.
Таймаут должен быть больше нуля.

Справка по аргументам:

```bash
python monitor.py --help
```

Просмотр состояния и логов контейнеров:

```bash
docker compose ps
docker compose logs camera-slow
```

Остановка и удаление контейнеров проекта:

```bash
docker compose down
```

## Локальный запуск эмулятора

```bash
python -m uvicorn api:app --reload
```

API доступен по адресу http://127.0.0.1:8000,
интерактивная документация — http://127.0.0.1:8000/docs.

Пример запуска с настройками:

```bash
DEVICE_ID=entrance-02 DEVICE_DELAY=2 \
  python -m uvicorn api:app --port 8001
```

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| DEVICE_ID | entrance-01 | Идентификатор устройства |
| DEVICE_DELAY | 0 | Задержка ответа `GET /state` в секундах |
| DEVICE_FAIL | 0 | Значение `1` включает HTTP 503 для `GET /state` |

Отрицательная задержка отклоняется при запуске.
Для изменения переменных окружения сервер нужно перезапустить.

## HTTP API

### Получить состояние

```bash
curl -i http://127.0.0.1:8000/state
```

Пример тела ответа:

```json
{
  "device_id": "entrance-01",
  "name": "camera",
  "status": "online",
  "resolution": "1920x1080",
  "fps": 25
}
```

### Изменить FPS

```bash
curl -i -X PATCH http://127.0.0.1:8000/settings \
  -H 'Content-Type: application/json' \
  -d '{"fps": 30}'
```

При успешном изменении API возвращает обновлённое состояние.
FPS должен быть целым числом больше нуля. Ноль и отрицательные значения
отклоняются с кодом 422 без изменения состояния.

## Формат отчёта

```json
{
  "elapsed_seconds": 2.04,
  "results": [
    {
      "url": "http://127.0.0.1:8002/state",
      "success": true,
      "state": {
        "device_id": "camera-fast",
        "name": "camera",
        "status": "online",
        "resolution": "1920x1080",
        "fps": 25
      }
    },
    {
      "url": "http://127.0.0.1:8003/state",
      "success": false,
      "error_type": "timeout",
      "error": "Время ожидания превышено"
    }
  ]
}
```

Категории ошибок: `http`, `timeout`, `network`, `invalid_json`.
Для HTTP-ошибок отчёт также содержит `status_code`.

Поле `status` описывает состояние, сообщаемое самим устройством.
Результат `success` показывает, удалось ли монитору получить состояние.

## Тесты

```bash
python -m pytest -q
```

Десять тестов проверяют:

- изменение FPS и отклонение нуля и отрицательных значений;
- проверку настроек и успешное обновление через API;
- обработку монитором успешного ответа, HTTP 503, таймаута,
  ошибки соединения и некорректного JSON.

API проверяется через TestClient, монитор — через MockTransport.
Для запуска тестов работающие эмуляторы не нужны.

## Ограничения

- Эмулятор не передаёт видео и не реализует RTSP или ONVIF.
- Состояние хранится в памяти процесса и сбрасывается при перезапуске.
- Через API настроек пока можно изменить только FPS.
- Аутентификация не реализована; Compose публикует порты только
  на локальном интерфейсе.
- Таймаут HTTPX ограничивает сетевые операции, а не задаёт строгий
  предел длительности всего опроса.
- Монитор обрабатывает некорректный JSON, но пока не проверяет
  структуру успешно разобранных данных камеры.
